- **正常输入**：规范 Pickle 封装、容器内文件和目录、空文件和空目录、多块复制、整文件及分块 SHA256、精确共享范围的独立副本、乱序偏移、未引用空隙，以及一条命令完成合成 ASAR 两版本差分。
- **格式和资源拒绝**：截断、过大或长度矛盾的头部，非零填充，重复 JSON 键，非法 UTF-8/代理码，解析前 JSON token/嵌套上限，巨型数字，不安全或保留路径，大小写/Unicode 冲突，以及条目、深度、文件大小、总量和清单预算。
- **条目和完整性拒绝**：链接、特殊文件、硬链接元数据，含义冲突的外置条目，范围越界或部分重叠，共享范围的完整性声明不一致，以及错误的整文件/分块哈希。
- **事务检查**：保留已有文件、目录和断开的符号链接；目标在原子交付前出现时不替换它；输入变动、写入失败、交付失败和不支持原子操作的主机不会交付成功输出。拒绝输入符号链接、硬链接和 FIFO；可捕获中断会清理本次暂存。
- **独立复核**：另一套原创封装生成器检查 UTF-8 字节长度与四种对齐位置、每个截断位置、Pickle 字段边界，以及小范围组合的独立区间判定。另查别名逐份计费、独立 inode、零长度别名、外置 FIFO 不被打开和 500 组固定种子的字节变异。该有限变异检查不等于广泛模糊测试。
- **不执行目标代码**：包含“若执行就写标记文件”的原创 JavaScript 样本只作为字节被提取，没有出现标记文件。
- **命令行与整体回滚**：两个 ASAR 命令均从其他工作目录执行。两版本任务已成功提取第一个输入后，若第二个 ASAR 含外置排除项，整个任务会回滚。新增外层竞态回归检查完整运行目录的交付目标不会被覆盖。

## 真实样本只读检查与严格提取的区别

三个已有的 Linux/Windows/macOS 产品容器均通过元数据清点，各有 25 个精确共享范围别名，外置文件分别为 3、6、10 个。**三个严格提取尝试全部在写出前拒绝，均未创建输出目录。**

没有打开外置配套内容、执行目标代码或在暂存中保留产品数据。没有重新下载或重新认证这些样本。容器哈希与元数据检查已完成，但并未重新核验每个成员的实际哈希；只有提取流程才会验证声明的成员哈希。

这些结果说明只读检查能识别当前覆盖缺口，不能据此声称三个官方包已经能完整解包或直接进行完整两版本差分。严格 packed-only 策略故意拒绝它们；外置配套目录的绑定、清点、缺失/变动/额外内容与哈希不匹配策略仍是后续工作。

## 尚未建立的保证

尚未进行原生 macOS/Windows 执行、广泛模糊测试、崩溃或断电测试、恶意并发祖先路径替换防御、签名验证，或真实产品的完整两版本差分。没有运行 REA 命令。元数据检查不证明完整应用，声明哈希也不认证发布方。

ASAR 提取、两版本运行目录和报告目录已使用原子不替换交付；独立 ZIP 提取仍保留原有静止父目录要求。该保证的适用范围与平台边界见 [SUPPORT.md](SUPPORT.md)，设计来源见 [ASAR-SOURCE-NOTES.md](ASAR-SOURCE-NOTES.md)。适配器复用已有快照与差分代码，没有将静态扫描扩展为运行时行为分析。
