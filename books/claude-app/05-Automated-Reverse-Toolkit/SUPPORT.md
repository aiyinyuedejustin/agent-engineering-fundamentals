# ASAR 适配器的支持范围与安全边界

本适配器用 Python 3.10+ 标准库，离线读取一个有明确容量上限的 ASAR 子集。它不安装依赖、不联网、不启动子进程，也不运行安装器、目标程序或 JavaScript，不从档案导入模块。

**先检查，再决定是否提取。** 只读检查成功，表示容器元数据符合本解析器的要求；它不保证整个应用已被覆盖，也不保证这个包能通过严格提取。

## 先检查 ASAR 再提取

在工具箱目录执行，或使用脚本的绝对路径。输出目录必须尚不存在，父目录必须已存在且由自己控制。

```sh
python3 -B reverse_toolkit.py inspect-asar --input "/path/to/app.asar"
python3 -B reverse_toolkit.py unpack-asar --input "/path/to/app.asar" --output "/path/to/private/new-tree"
python3 -B diff-versions.py "/path/to/old.asar" "/path/to/new.asar" --output "/path/to/private/new-diff"
```

| 检查结果 | 接下来怎么做 | 能得出的结论 |
|---|---|---|
| `inspect-asar` 拒绝输入 | 停止；先查格式、路径、大小或范围错误 | 未通过本工具的元数据检查 |
| 检查成功，`extractable_within_subset` 为 `false` | 查看 `exclusions`；不要继续假定能够完整提取 | 有链接或外置内容，当前严格提取会整体拒绝 |
| 检查成功，`extractable_within_subset` 为 `true` | 可尝试 `unpack-asar`；两版本都满足条件时可用 `diff-versions.py` | 元数据符合子集；成员哈希和读取时的输入稳定性仍待提取阶段验证 |
| 严格提取成功 | 用同一范围的目录制作静态快照、比较版本 | 已提取所支持的打包内容；仍不证明完整应用、发布方身份或运行时行为 |

`inspect-asar` 只返回容器身份、数量、明确排除的路径及兼容性元数据。它计算容器 SHA-256，但不读取 `.asar.unpacked` 外置配套目录、不跟随链接、不写出解包树，也不逐个验证成员哈希。输出不是功能快照，不能交给 `diff_snapshots`；`complete_application` 和 `publisher_authenticity_verified` 始终为 `false`。

`unpack-asar` 只提取完全位于 ASAR 内的受支持内容（packed-only）。只要任一条目是链接或依赖外置配套内容（sidecar），整次提取就会失败，不交付残缺目录，也没有“跳过 sidecar”的开关。`diff-versions.py` 按不区分大小写的 `.asar` 后缀选择适配器，再验证实际字节；后缀不证明格式或来源。任一 ASAR 输入被拒绝，整个两版本任务都会在交付报告前撤销。其他普通文件输入仍使用 ZIP 适配器。

## 支持的 ASAR 表示

- Electron 规范的双 Pickle 封装：前缀由四个小端 32 位字段组成，UTF-8 JSON 头须正确对齐并以零填充；文件偏移从头部之后的数据区起算。
- 普通目录与打包在容器内的常规文件。接受可选的 `executable` 元数据，但不恢复可执行权限，输出文件不可执行。
- 零字节文件、空目录、未按偏移排列的范围，以及数据区内未被引用的空隙。未引用字节会计入报告，但不会提取。
- 可选的 SHA256 整文件与分块完整性信息。所有声明的哈希都在交付前核验；没有完整性声明的文件仍可提取，结果会记录有声明的文件数量。这些哈希属于输入自行声明的信息，不认证发布方。
- 精确共享字节范围：偏移和大小必须都相同，归一化后的完整性声明也必须一致，包括“有声明”与“无声明”的区别。每个逻辑文件分别复制，不创建硬链接；每个输出副本分别计入总字节预算。**部分重叠的范围一律拒绝。**

## 明确拒绝或不处理的内容

检查会列出链接和外置条目，提取会拒绝它们。目录的 `unpacked` 状态会传给子项；同一条目既标成外置又声明容器内偏移，连检查也会拒绝。未知元数据一律拒绝，包括硬链接、特殊文件、设备和 `mode` 扩展，不做宽松猜测。

所有路径分量必须是可移植的相对名称。拒绝路径穿越、绝对路径、分量内分隔符、盘符/ADS 语法、控制字符、未配对 Unicode 代理码、保留设备名、空名称、末尾点或空格、重复 JSON 键，以及大小写或 Unicode 归一化后的路径冲突。

还会拒绝文件/目录含义不明的节点、错误数值类型、负数或超限大小、不规范的十进制偏移、浮点数或非有限数、截断封装、互相矛盾的 Pickle 长度、非零填充，以及超出容器的字节范围。

本解析器有意只覆盖 ASAR 生态的一小部分。它不推断如何解码经过转换或加密的内容。嵌套档案只是普通字节，不会递归展开。

## 默认资源上限

沿用现有 `Limits` 对象。ASAR 将 `max_central_bytes` 用作头部预算；不会把 ZIP 专用参数误当作 ASAR 压缩比上限。

| 资源 | 默认上限 |
|---|---:|
| 容器字节，打开前检查 | 256 MiB |
| 头部 Pickle 字节，分配头部缓冲前检查 | 16 MiB |
| JSON token，构造 JSON 对象前计数 | 200,000 |
| 档案条目，含目录和排除项 | 20,000 |
| 单文件字节 | 64 MiB |
| 逻辑打包字节，精确别名逐份计入 | 512 MiB |
| 路径分量数 | 64 |
| 单路径 UTF-8 字节 | 4,096 |
| 展开路径清单预算，含每条记录开销 | 16 MiB |
| 数据读写块 | 不超过 64 KiB |

JSON 嵌套和整数转换也在对象构造前受限。两版本命令固定使用默认上限，没有绕过开关；独立命令保留工具箱原有的条目数、单文件和总量参数。库调用者可提供正整数上限，但路径深度不得超过 128。

## 输出事务与主机边界

输入必须是链接数为 1 的普通文件，分析期间保持静止。拒绝末尾分量是符号链接的输入和特殊文件；读取前后核对文件描述符与路径身份，包括大小、时间戳和 inode。现有祖先路径及输出父目录必须可信、稳定。**这不是防御同一用户下的恶意进程、祖先路径替换或文件系统失陷的沙箱。**

元数据全部通过后，才在输出旁创建新的私有暂存目录。交付前核验所有已声明的成员哈希，并再次检查输入身份；任何交付前错误都会清理本次拥有的暂存树。输入文件不会被修改。突然终止、断电或清理失败仍可能留下暂存目录。

以下输出使用同一个原子的“不替换既有路径”操作：

| 输出路径 | 当前交付方式 |
|---|---|
| `unpack-asar` 的解包目录 | `atomic_publish` |
| `diff-versions.py` 的完整运行目录 | `atomic_publish` |
| `compare` / `diff` 的报告目录（`write_report`） | `atomic_publish` |
| 独立 `unpack-zip` 的解包目录 | 原有 ZIP 实现，仍要求输出父目录静止；不具有本次新增的原子不替换保证 |

Linux 使用标准库 `ctypes` 调用 `renameat2(RENAME_NOREPLACE)`；macOS 代码使用 `renamex_np(RENAME_EXCL)`；Windows 代码使用 `os.rename`。不支持的主机或文件系统会拒绝交付，没有 POSIX“先检查、再普通 rename”的降级路径。**实际执行只在 Linux 验证；macOS、Windows 分支尚未在原生系统上运行。** `ctypes` 只调用主机已经加载的 libc，不加载目标提供的本机代码。这里保证原子可见性，不保证崩溃后持久性，也没有基于 `fsync` 的承诺。

POSIX 下，ASAR 解包根和目录使用 `0700`，文件使用 `0600`；Windows 隐私保障取决于已有用户目录及 ACL。原子不替换只覆盖上述最终交付操作，不解除可信、稳定祖先路径和隔离工作区的要求。

要完整比较这类官方包，外置配套内容策略仍待实现和审查：将明确的配套目录绑定到所选档案，安全清点每个配套文件，保留缺失、变动和额外内容的覆盖信息，并按明确的不匹配策略验证声明哈希。不能把未纳入的内容当作“功能已删除”。已有的可选 REA 流程可另行审查使用；本适配器不会安装或调用它。
