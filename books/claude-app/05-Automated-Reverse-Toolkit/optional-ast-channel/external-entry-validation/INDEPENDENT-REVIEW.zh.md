# 正式外置入口：独立复核摘要

**结论：限定范围内通过。** 结果支持固定 Acorn 8.17.0 的正式依赖兼容与声明范围内的语法候选提取，不证明语义完整性。

## 交叉核验

- 对保存的官方 npm 元数据、精确锁文件和实际 tarball 独立重算 SHA-512、SHA-1，结果一致；安装的 package.json 与 dist/acorn.js 与该 tarball 对应成员逐字节一致。本复核未再次获取 registry 元数据，未验证发布签名，也不构成恶意代码审计。
- 60 份正式 CLI 和 7 份收紧预算 API 报告的依赖标记、模块摘要及规范报告身份摘要通过核验；CLI 输入与报告摘要亦一致。52 个既有 fixture 为45成功、7预期拒绝；另8个CLI、7个API检查单独计数，不是原89项测试套件的外置重跑。
- 实现明确通过外置模块路径加载 Acorn，外置失败无内部模块回退。百万 token 输入按结构独立重建、计数并核对存档：1,000,000通过，加一个分号至1,000,001则整文件拒绝；未重复运行该大预算测试。

## 独立微型抽查

4个原创CLI场景均通过：

1. 正则和模板原始文本不产生伪候选；模板插值中的真实调用保留，动态成员调用排除。
2. 静态与动态 import 引用一个实际存在、语法非法的依赖文件，仍只解析当前输入。
3. 不含 import 的输入包含文件写入、process.exit、throw；仍返回后方语法候选且未生成哨兵文件。
4. 有效候选后追加不支持的 TypeScript 语法，整文件拒绝、零候选。

另一个缺失外置依赖检查按预期退出2、零候选，没有内部依赖回退。

## 证据边界

原 fixture oracle 比较预设状态及 category/key 多重集，不是所有记录字段、所有字节锚点或业务语义的完整判据。Unicode专项有锚点断言，不应推广为所有锚点均已独立验证。

把不存在的 import 和执行哨兵放在同一输入中，哨兵缺席可能仅由导入失败造成。因此，独立抽查将“无导入的执行陷阱”和“现存非法依赖不解析”分开验证，结合加载与解析代码路径审阅，增强了证据；仍不等于系统调用追踪或操作系统沙箱。可信解析器代码本身会执行。

候选交付文件的清单与摘要通过核验；所审文件不含第三方源码、缓存、产品文本、私有绝对路径或明显凭据。历史内部测试依赖结果和旧 coverage 不因此改变；不支持其他版本、安装布局或平台的外推。

## 便携复验

附带的 verify-fixtures.py 另经静态审阅与帮助入口抽查：接收显式外置 Acorn 路径，使用相邻工具目录或 --tool-dir，在临时目录重跑既有52个原创fixture；无需私有元数据或缓存，不会自行联网或安装。其复验范围及结果计数说明清楚。独立复核未再运行全部52条，便携重跑不得累加为新的52项覆盖。
