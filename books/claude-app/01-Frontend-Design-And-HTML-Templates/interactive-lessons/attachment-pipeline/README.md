# 附件实验台：从可见到可发送

[打开交互课](index.html) · [返回前端设计学习区](../../README.md)

一节原创、可离线打开的交互课。入口是 `index.html`，所有样式与逻辑内联；运行时不依赖 npm、外部字体、网络或服务器。文件、账户、草稿和返回结果都是固定合成数据，没有文件选择器，也不接收用户上传。

**定位：**用一个可重复操作的状态模型解释卷五里的客户端边界，不复刻 Claude 产品界面，不声明观察到其当前运行行为。48 B、4 个槽位、1–3 个模拟步骤均为本课自定参数，不是产品限制。

## 先看见什么，再理解什么

阅读入口中的四个场景即可走完课程；每个场景都有自己的预测题与三步操作指南。

### 01 · 顺序与字节

初始同时加入两条合成文本：

- 槽位 1：“这是中文便签”，6 个汉字，UTF-8 为 18 B，处理需要 3 步。
- 槽位 2：“Hi 🌱”，JavaScript 字符串长度为 5，UTF-8 为 7 B，处理需要 1 步。

初始账本是确认 0 B、预留 25 B。推进一次，第二项先完成：确认 7 B、预留 18 B，总占用仍是 25 B。再推进两次，第一项完成：确认 25 B、预留 0 B。

卡片始终留在原槽位；Send 快照也按槽位 1、2 排列。完成不是往数组末尾追加，而是按稳定 client ID 回写原记录。再添加同名便签，会得到另一个 client ID。

对应卷五：5.1 稳定本地记录、5.3 输入索引与完成先后、5.4 UTF-8 账本、5.11 客户端集合顺序。不能把这一数组顺序外推为完整模型 prompt 的排序。

### 02 · 预留与准入

18 B 便签仍在处理时加入 36 B 长段落：18 + 36 > 48，因此后者被拒绝。被拒绝的卡片可见，但没有占用预算，且阻断 Send。

取消便签后，预留降为 0。点击长段落的“重新检查预算”，它才进入处理并预留 36 B。两步后确认 36 B。取消的槽位保留痕迹，但不属于待发送集合。

这同时解释三个界面判断：卡片存在 ≠ 准入成功；在途附件 ≠ 不占额度；取消 ≠ 隐式重新开始其他失败项。

对应卷五：5.4 并发预留与幂等释放、5.7 分型错误、5.8 卡片作为状态投影。本课选择明确拒绝，没有实现产品条件下可能存在的“提升为文件上传”路线。

### 03 · 等待与重试

PDF 卡停在 `held`，必须确认合成文件引用路线；图像任务首次经过两步后固定进入 `retryable`。等待不会被时间自动解决，已知可恢复错误也不会无限自动重试。

确认 PDF 路线、手动重试图像后，各自再推进两步可就绪。两者都不占内联文本字节，最终快照中包含 `fake:` 引用。0 B 不代表没有附件、不消耗模型上下文或上传成功的真实证据。

对应卷五：5.3 路线选择、5.5 文件引用与文本表示、5.7 等待和可重试错误分型。本课不进行真实 PDF 提取、图像预处理、OCR 或传输。

### 04 · 取消与迟到

1. 取消正在处理的槽位 1。预留释放一次，卡片变为取消痕迹。
2. 点击“投递迟到结果”，故意让一个忽略取消信号的旧回调成功到达。
3. 守卫拒绝写回：卡片不会复活，预算不会回弹。
4. 在仍有在途任务时切换账户或草稿；再投递旧结果，新草稿必须保持空白。
5. “重开本草稿”保留相同账户与草稿名，却增加 generation。旧结果仍无效，说明只检查名称不够。

票据包含账户、草稿、代次、client ID、尝试编号；写回还要求记录目前处于处理中。重试建立新尝试编号，因此前一次尝试的成功不能覆盖新尝试。重复成功也不会重复计费。

对应卷五：5.7 取消与归属、5.8 卡片一致性、5.9 草稿代次。**本课只证明本地状态隔离，不证明服务端已撤销操作、删除对象或完成跨账户权限隔离。**

## Send 为什么能用，或不能用

所有卡片、字节账本与 Send 都读取同一模型。提交条件为：

1. 存在固定示例正文或至少一个未取消的已就绪附件。
2. 每个未取消附件都已就绪。
3. 没有等待、处理中、拒绝或可重试失败项。

按钮使用 `aria-disabled` 保持可聚焦，旁边解释具体阻断；点击时仍会执行逻辑守卫。正文不会绕过附件阻断。取消项不进入快照。快照是点击时的固定副本，后续编辑不会改写它；没有网络发送。这里刻意不清空就绪卡片，方便比较提交前后状态。

## 状态与工程合同

- `held`：等待路线，尚未启动任务。
- `deriving`：处理中；内联文本持有预留。
- `ready`：可用的内联文本或合成文件引用。
- `rejected`：预算不允许；保留诊断，不扣款。
- `retryable`：固定合成的可恢复错误；等待手动重试。
- `cancelled`：退出提交集合；释放预算，保留可见槽位痕迹。

账本不变式：`confirmed >= 0`、`reserved >= 0`、`confirmed + reserved <= 48`。只有 `ready` 持有确认字节，只有 `deriving` 持有预留字节。应用模型不公开可变状态，测试检查接口返回深拷贝；独立构造器用于模型单测。

固定槽位不循环利用，最多展示四个历史入场位置；“重开本草稿”或选择场景重新分配。这样不会把后加入项目插到已取消的旧位置前面。这个限制是教学简化，不是推荐生产列表必须有空洞。

## 键盘与辅助技术

- 原生按钮、下拉框与复选框；Tab / Shift+Tab 导航，Enter / 空格激活，方向键选择下拉选项。
- 卡片操作消失后焦点回到同一槽位；卡片重绘不会把尚存在的操作焦点丢到页面顶部。
- 清晰的 `:focus-visible`、跳过导航链接、关联标签与 Send 原因说明。
- 状态有文字，账本有完整文本，不只依赖颜色；单独的 polite、atomic 状态区播报结果、预留/确认额度及提交资格。
- 减少动态效果偏好关闭账本宽度过渡。没有自动计时、自动滚动、模态框或自定义键盘陷阱。

这些是实现合同。jsdom 不能证明真实 Tab 顺序、浏览器布局、读屏实际播报或 WCAG 合规。

## 本地验证

打开课程不需要安装依赖。维护测试使用 Node.js 18 或更新版本，以及固定版本的 jsdom 26.1.0；`test.cjs` 从标准 Node.js 模块路径加载 `jsdom`，不依赖研究工作区或私有目录。

在本课目录打开终端。以下 macOS / Linux 命令把 HTML 与测试复制到一个全新的临时目录，再只在该目录安装测试依赖；不会给仓库或课程运行页添加依赖：

```sh
test_dir="$(mktemp -d)"
cp index.html test.cjs "$test_dir/"
npm install --prefix "$test_dir" --no-save --no-package-lock --ignore-scripts jsdom@26.1.0
node --test --test-reporter=tap "$test_dir/test.cjs"
```

首次安装需要可访问 npm 软件包注册表。Windows 可在新建的空目录放入 `index.html` 与 `test.cjs`，进入该目录后执行同样的 `npm install --no-save --no-package-lock --ignore-scripts jsdom@26.1.0` 和 `node --test --test-reporter=tap test.cjs`。临时目录可在测试结束后自行清理。

共 22 项检查，包含：实际 UTF-8、异步完成顺序、并发准入、边界值、同名独立身份、重复清理、重复完成、账户/草稿切换、同名新代次、旧尝试票据、等待与重试、Send 双重守卫、不可变快照、焦点恢复、实时播报、静态 ARIA、零外部资源与 500 步确定性状态压力测试。

[验证元数据](validation.json) 记录本目录文件的 SHA-256、验证范围和运行环境。源码来自本研究的原创合成实现；HTML 与原始交互课一致。22 项 Node/jsdom 检查已通过；这不等于真实浏览器布局、实际键盘导航或读屏通过。

## 真实浏览器验收清单

以下是发布时应另行完成的检查，不是已通过的结论。浏览器检查结果应单独记录；不要用 Node/jsdom 结果代替。

1. 在桌面 1440 px、手机 390 px 与 320 px 宽度下检查横向溢出，确认固定槽位、账本和 Send 原因清楚可读。
2. 只用键盘：跳过导航链接有效；按钮可用 Enter / 空格激活；下拉框可用方向键选择；取消后焦点留在原槽位，下一次 Tab 进入后续正常操作。
3. 场景 01：一次推进后槽位 2 先就绪，账本为预留 18 B、确认 7 B；最终 Send 快照仍按槽位 1、2 排列。
4. 场景 02：18 + 36 B 被拒绝；取消 18 B 后手动重新检查，36 B 才入场；旧回调不会恢复已释放的额度。
5. 场景 03：等待路线与可重试失败有不同原因；确认或重试后可就绪；两个引用仍是 0 B 内联额度。
6. 场景 04：取消、切草稿、切账户、重开同名草稿后分别投递旧回调；没有卡片复活、串草稿或重复计费。
7. Send：有正文但有未完成项仍阻断；无正文有就绪附件可生成；取消项不进入快照；旧快照保持点击时的数据。
8. 检查 200% 缩放、减少动态效果偏好及至少一套读屏：焦点可见、标签明确、状态不重复播报，并说明阻断原因。
9. 使用浏览器开发者工具检查没有脚本错误或外部请求；发布平台若注入额外资源，需要单独核对。

修改 HTML 后，应重跑 Node 检查、更新哈希并重复受影响的浏览器验收。截图本身不能证明真实键盘或读屏的完整结果。
