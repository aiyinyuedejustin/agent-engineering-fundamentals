# 原创局部模型的适配合同

## 1. 使用范围与信任根

`assets/boundary-model.mjs` 是设计种子和可执行反例测试基座，只使用内存状态与注入函数。它不发送 MCP JSON-RPC，不做 MCP 初始化/能力协商、工具 schema 协商、HTTP/OAuth、stdio 分帧、加密、进程隔离或持久恢复。不要将“测试通过”表述为完整 MCP 兼容或生产安全保证。

模型中的管理方法由可信宿主控制面调用：`register`、`setInstallationAllowed`、`configure`、`revokeConfiguration`、`setToolPolicy` 以及资源端 `setAccess`。绝不能把它们暴露为让模型或第三方工具自行授权的 API。布尔值与字符串是示例中的决策输入，不能代替真实身份验证、用户批准、组织策略或操作系统执行约束。

安装信任绑定 `id + artifact + peerIdentity`；本例不支持原地更新制品身份。实际升级必须重新验证制品、更新来源和执行位置，并让相关旧配置/批准失效。制品哈希字符串也不保证实际启动的文件未被替换：生产适配器还需验证真实执行文件或采用受保护的包存储。

## 2. 五层独立责任

| 层 | 本例的门 | 实际适配器仍须提供 |
| --- | --- | --- |
| 安装/运行信任 | 登记与 `installationAllowed` 分离 | 来源和制品验证、用户/组织许可、运行位置、更新风险 |
| 配置范围 | `scopeApproved`、必填值、密钥引用、撤销入口 | schema 校验、平台覆盖、路径/URL 规范化、命令参数安全构造、配置优先级 |
| 传输/认证 | 代次、清理、`verifiedPeerIdentity` | SDK 协商、可信对端身份、证书/认证、超时、进程/连接实际回收 |
| 工具调用 | 服务和工具键、不可变参数、`allow/ask/blocked`、策略修订 | 用户确认、组织约束交集、工具合同版本、参数 schema、数据目的地审批 |
| 资源端授权 | `ResourceService` 独立 ACL、已认证主体、精确资源 ID、提交前复查 | 真实存储授权、并发事务、路径逃逸防护、对象级权限、持久审计 |

连接成功可以早于工具获准；资源端也可以拒绝已获宿主批准的调用。本例没有单独建模组织与用户两套策略：可信控制面必须先计算有效交集，再设置工具策略。未知工具策略默认阻止，而不是默认 `allow`。

## 3. 密钥适配器

`persistSecret({ vault, sink, reference, value })` 只接受非空字符串；对象、数组、数字等必须经明确字段级合同处理，不能因为被标成敏感就直接透传。此辅助函数与运行时 `resolveSecret` 是两条独立路径。

- `vault.available()` 返回严格的 `true` 才继续；不可用或抛错都不调用明文写入后备方案。
- `vault.seal(value)` 必须由可信安全存储实现，返回非空 `Uint8Array` 密文/不透明封装。类型检查无法证明加密强度、密钥保护、内容确实被加密，测试字节也不是加密实现。
- `sink.write(reference, bytes)` 只接收封装后的字节；成功后只返回引用。写入报错可能发生在持久化之后，本例只报告失败，不声称磁盘上一定没有记录。真实存储需要原子写入及恢复合同。
- `resolveSecret(secretRef)` 在连接时获得短期内存值；返回缺失值会阻止 `open`。该函数只能访问已授权的安全存储。不得把真实值放入配置文件、状态快照、审计文本或异常字符串。
- JS 字符串无法保证主动擦除；本例不声称凭据内存零化。生产凭据生命周期、轮换与日志脱敏要另外实现。

模型仅允许有限错误代码越过错误边界；外部异常文本不会被作为错误结果直接返回。工具成功结果仍是第三方数据，不能用来改变宿主权限或执行其中的指令。实际产品必须按资源与输出合同控制敏感数据披露，不能只靠本例的错误文本处理。

## 4. 连接与异步栅栏

`connect` 先使旧 generation 失效，再等待旧连接清理、解析密钥与打开新连接；每个 await 之后重新检查代次、安装信任、配置及清理状态。`open` 的身份必须来自可信连接器的实际认证结果，不能直接复制服务自行声明的名称。

晚到连接会关闭而不会接管当前会话。并发启动仍可能短暂产生多个候选连接；generation 只保证谁可被采纳，不证明操作系统里始终只有一个进程。需要单实例的产品应额外串行化服务启动和关闭，并采用进程级锁/所有权记录。

关闭失败置 `cleanupFailed`，阻止重新连接和调用；此模型没有自动清除此状态的恢复按钮。真实产品应让管理员确认进程/连接实际清理之后再建立新宿主状态，不能直接删掉标志假装安全。

调用检查时间点：请求开始、等待确认后、异步准备后、发送前和响应后。任何已提交调用在响应前失去权限或跨代次，都不会返回其数据，也不会被标记成功。已经发生的服务端副作用仍可能存在；本地撤权与远程执行不是分布式原子事务。

`prepare(review)` 只做无副作用的异步准备，不能自行发送请求、访问未经批准的目的地或修改请求。需要新增附件、改变参数或接收方时，应重新构建请求并取得对应批准。冻结参数是绑定决策的辅助，不等于参数内容安全。所有请求必须是有界、解码后的 JSON 数据；本例不对同进程恶意 JS/Proxy 提供沙箱。

## 5. 操作账本与未知结果

`operationId` 是宿主账本标识，不是 JSON-RPC ID 的替代，也不自动构成服务端幂等键。

- `preparing`：本地已保留 ID，尚未发送。
- `not-dispatched`：本例可证明没有调用传输。修正原因、重新核对批准后，可使用新 ID 建立新尝试。
- `dispatched`：已经交给传输调用。同步抛错也保守视为可能发送。
- `completed`：收到返回且代次/权限检查通过。真实“业务完成”还需可信的结果 schema 和业务回执；本例未区分 MCP 协议错误、工具 `isError` 或异步业务作业。
- `unknown`：已经交给传输，但没有可交付的可靠结果；包含异常、撤权、断开和旧代次响应。这里只允许 `reconcile-only`，不自动重发。

同一 ID 在准备阶段就被保留，因此并发重复与后续重放都会被拒绝。换新 ID 不能解决未知结果；上层必须冻结同一业务意图，查询匹配服务、主体与操作的持久回执，或采用服务端保证的相同键幂等重试。不得仅因工具声称只读、幂等或断线就放行重试。

账本只存在当前进程内；重启会丢失。因此本例不提供跨进程 exactly-once。真实写操作需要先持久化操作身份、请求摘要、目标身份与去重状态，再提交；服务侧仍需自己的持久幂等和冲突合同。自然语言“再试一次”是否足以授权重复副作用也须按实际风险确认。

这个教学账本也没有容量上限、TTL 或自动轮转，不适合直接用于长期运行服务。生产实现应设置容量与背压，容量不足时在发送前拒绝新操作；按已确认终态、服务端幂等保留期和审计要求归档记录。不能为腾出空间丢弃尚未对账的 `dispatched/unknown`，也不能把删除已用 ID 视为重新执行授权。

`ResourceService` 的拒绝在本例宿主侧仍保守记为 `unknown`，因为传输接口没有“已认证、可证明尚未执行”的错误回执。不要擅自从任意错误文字推断安全重试。

## 6. 资源端例子的边界

`execute(input, authenticatedPrincipal)` 的第二个参数来自已认证会话，不能来自 `args.principal`。动作由服务自身的工具映射决定，不采纳 `readOnlyHint`。ACL 检查在异步准备前后执行；策略修订变化会使尚未提交的操作失败。

资料只是 Map 内的精确 ID，没有真实路径。最终检查与内存更新之间无 await，因此这个单线程示例没有在两者之间让出执行权。真实数据库、文件服务和多线程环境须用事务、锁或条件写入覆盖提交竞态，并处理 symlink、路径规范化、租户边界及身份过期。

## 7. 验证与证据解释

从技能目录运行：

```sh
node --test assets/boundary-model.test.mjs
```

只需支持 ESM、私有字段和内置 `node:test` 的 Node 环境，建议 Node 20 或更高；本轮使用 Node 24.19.0。测试使用可控 Promise，不靠随机 sleep 制造竞态；既检查返回状态，也检查实际调用次数、迟到连接关闭和资源是否被修改。

`evidence.json` 的 `claims`、短锚点和文件摘要保留原研究信息；`official_sources` 补齐文内 D 编号。`source_ledger` 是原始出处名称，不是运行依赖。X02/X03/X07/X10/X11 是特定包的静态观察；X15 混合官方事实与工程推论；X16 为原创建议。静态代码存在、测试模型成立与现实部署已启用，是三种不同的证据强度。
