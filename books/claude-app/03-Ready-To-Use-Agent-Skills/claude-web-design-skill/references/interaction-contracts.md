# 原创交互补充：模态与安全紧凑模式

仅在产品确实需要时使用。可复制 [完整小例](../assets/interaction-recipes.html) 与同目录的 [tokens.css](../assets/tokens.css)，直接打开 HTML；不需要本书其他文件或网络依赖。这是原创教学实现，不是 Claude 运行时代码。原骨架的作品侧栏是非模态，不能用它的 Escape 检查代替模态验收。

## 原生 dialog 契约

- **打开与初始焦点**：用 `showModal()`，防止重复打开；不要通过 `open` 属性、`show()` 或仅 `aria-modal` 假装模态。给窗口可访问名称。短表单用 `autofocus` 指明首要输入；长说明可把初始焦点放在带 `tabindex="-1"` 的开头标题，避免跳过上下文；不要给 dialog 本身加 tabindex。[HTML dialog](https://html.spec.whatwg.org/multipage/interactive-elements.html#the-dialog-element)、[APG 初始焦点建议](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
- **背景与键盘**：原生模态使同一文档的背景不可交互；保留浏览器的焦点处理，不叠加一个静态首尾节点列表的 Tab 陷阱。实际验收 Tab、Shift+Tab 不落到背景控件；浏览器界面可能获得焦点，不能声称每个浏览器都严格「最后一个 → 第一个」循环。若产品要求该严格循环，另行实现并验证动态、隐藏、禁用控件及跨浏览器行为。
- **退出**：保留明确的关闭按钮。例子中按钮调用 `close('cancel')`；Escape 的原生关闭请求会触发 `cancel`，不阻止默认行为，让浏览器关闭，再统一走 `close` 事件。单独调用 `close()` 不会先触发 `cancel`。没有额外实现点击遮罩关闭。取消保留草稿，只有成功的本地提交才清空。
- **返回**：打开时记住触发按钮；在 `close` 中还原焦点，触发按钮消失、禁用或不可见时转到合理的稳定位置。示例用页面标题作备用目标。不要在 `cancel` 中过早把焦点送回仍不可交互的背景；不要移除 `open` 属性代替正常关闭。

## 安全紧凑配方

紧凑优先压缩导航、工具栏与区域边缘的空白，正文尺寸/行高、阅读宽度、命中区域独立建 token。例子只切换 `--chrome-gap`、`--chrome-pad`、`--section-pad`；保持中文正文 `1rem / 1.75`、最大 `48rem` 阅读宽度、按钮双轴至少 `44px`。`data-density` 表示布局，切换按钮的 `aria-pressed` 同步；主题、密度和草稿都只在当前页内存中，刷新即清除。

对 `any-pointer: coarse` 增加至 `48px` 命中区域并保留间隔，以覆盖有触屏的混合输入设备；这只是保守增强，媒体查询不能替代真机触摸、混合输入和缩放检查。图标的视觉尺寸可以较小，但不要以不可见重叠热区扩大它，也不要依赖 hover 才显示关键操作。

尺寸口径不能互换：

- 本技能原骨架按钮最小高度是 `44px`；新例子同时约束最小宽高。这里的 44/48px 是原创触达选择。
- 若已有另一原创模板采用 base/comfortable `40/48px` 控件，保持其命名与来源说明；40px 的视觉控件不能自动算作 44px 双轴命中区域。
- 观察到的 CDS base/comfortable `24/32px` 是指定版本的静态控件值，不是本配方，也不说明触达区域或可访问性合规。
- [WCAG 2.2 目标尺寸最低要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)为 24×24 CSS px，存在间距等例外；[增强要求](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)为 44×44 CSS px，也有例外。44px 不是所有控件的无条件 AA 要求，仅有最小高度也不能证明达标。

## 检验与反例

运行 `node --test assets/*.test.mjs`。原有颜色/骨架检查与新增静态、模拟 DOM 测试只检查包内产物；它们不证明浏览器原生模态、CSS 计算布局或辅助技术行为。改造、内嵌或复制到新页面后，应对最终页面重做同类检查，不能拿包内测试通过替它验收。

在最终页面实测：

1. 从键盘与指针各打开一次，检查名称、初始焦点、重复打开与关闭后重开；Tab/Shift+Tab 不进入背景，背景点击不触发操作。
2. 分别点击关闭、按 Escape、校验失败、成功提交。校验失败留在窗口；取消保留草稿；返回原触发点，移除触发点时返回备用位置。用真实按键验证 Escape，人工派发 `cancel` 事件不能证明原生派发。
3. 在两种主题、两种密度、375/768/1280px 与 200% 缩放下测量正文、按钮双轴命中区域和间隔；检查中文长文、长路径、滚动和触屏。主题或密度切换不能丢焦点或改变草稿。
4. 用目标浏览器及辅助技术确认名称/说明、读序和模态范围。记录真实跑过的环境；未测项目写「未验证」。

**Anti-Patterns**：把 `[open]` 当作模态；全局捕获 Escape 关闭任何浮层；关闭时直接删节点却不安排焦点；将脚本模拟的 Tab 循环当作浏览器证据；用缩小根字号或正文、压缩命中区域来实现 compact；把 CDS 观察值、40/48px 原创模板与本例的触达尺寸混为一组。

## 焦点交接与快捷键边界

把焦点与监听器一起纳入组件的生命周期；每次隐藏、替换或卸载，都要知道用户接下来从哪里继续。

三条规则：

1. 模态打开时，背景业务快捷键不得继续执行。原生模态并不会替应用取消 document 上的键盘监听；集中判断当前模态，明确消费应用接管的组合键，并保留输入法与 `defaultPrevented` 守卫。
2. 隐藏面板前先记录它是否包含当前焦点；是则交给可见的新标签，否则不抢焦点。同步更新 `hidden`、`aria-selected` 与 `tabIndex`；校验失败留在编辑位置。
3. 关闭返回本次真实 opener：点击取 `event.currentTarget`，快捷键取打开前 `activeElement`。重复打开不覆盖；节点脱离、隐藏、禁用或 inert 时改投稳定目标，并检查实际聚焦结果。

把关闭后的归还集中在 `close` 事件；卸载前与宿主交接焦点，再撤回监听和移除子树。后台完成不应抢走其他输入的焦点。

四条自测：

- 模态内按背景“新建”快捷键：窗口仍在、背景草稿不变；关闭后才恢复背景动作。
- 在编辑器内触发有效预览：焦点到可见标签；无效预览留在编辑器；面板外更新按钮不被无条件抢焦点。
- 从两个不同控件分别唤起，测试 Escape、关闭按钮与重复打开：每次回到真实来源，未提交草稿保留。
- 打开后重绘来源列表，再关闭或卸载组件：旧节点已失效，焦点仍落在宿主认可的可用位置。

模拟 DOM 验证节点身份、状态和动作分支；真实浏览器验证原生焦点、Tab、Escape 与布局。分别记录证据，不将前者当作后者。
