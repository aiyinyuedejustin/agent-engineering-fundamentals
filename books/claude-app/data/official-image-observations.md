# Claude 官方截图：视觉观察与证据边界

观察日期：2026-10-14（UTC）。本报告只分析从已核实的官方文章链接下载的 11 张原始图片。11 张均成功下载并通过 view_image 实际查看；尺寸与 SHA-256 已登记在 accompanying JSON。没有运行 Claude、登录账号、安装应用，也没有把图片重新发布或附入用户交付物。

## 最重要的结论

1. 最能稳定借鉴的是关系：输入面明显大于工具面、操作按任务分组、细边框和留白承担多数分隔、少量实色控件承担动作或状态强调。证据不支持把任何一个橙色、圆角或字体定义为全应用唯一规范。
2. 对话输入、系统设置与语音状态使用了不同的强调方式：截图中的发送箭头是暖橙色，Cowork instructions 的 Save 是黑底白字，活跃语音 Stop 是浅蓝底蓝字。它们不是同一主按钮的简单换皮。
3. 能直接确认 Desktop 独有形态的是 Mac Quick Entry：一条带明显浮层阴影的低矮横向输入条。其他近期图多为 web/desktop 共用裁切，不能证明原生桌面标题栏、导航或整窗布局。
4. 2024 年 Projects 图有米色工作面、书刊式衬线标题/回复、并排对话和 Artifact。它们有明确历史价值，但不能冒充 2026 年当前 Desktop。图片外围紫色纹理、放大光标、拖拽文件浮标属于演示包装，不应收进应用设计 token。
5. “官方文档当前可访问”不等于“图片拍摄于今天”。例如 composer 写着 Opus 4.5，另一张 voice crop 写着 Opus 4.6；本组图不能确定为同一版本或同一账号。

## A. 优先证据：输入、Quick Entry、设置

### A1. 通用 composer 裁切（OV06-IMG1，1442 × 334）

来源：[Get started with Claude](https://support.claude.com/en/articles/8114491-get-started-with-claude)。拍摄日期未知；只能称为该文档展示的界面样本。

直接观察：
- 一个横向拉长、白色内面的圆角输入容器，置于微暖的浅色外背景上；薄边线和宽而淡的阴影共同分开内外层。
- 输入提示位于左上，宽大的空白输入区域占主体。底部另成一条操作行，输入和工具具有明确的上下层次。
- 左下是加号和一个浅蓝底的时钟形线性图标；后者带底色，前者没有。右下是模型名称、下拉箭头，再接暖橙色圆角方形发送按钮。
- 左侧工具形成一组，右侧决策/提交形成一组，中间保留显著空白。模型与发送在同一水平带内，发送最靠近右边缘。
- 大多数文字与线性图标使用中性灰阶。发送按钮与浅蓝工具状态是少数色彩焦点。

解释而非事实：可以把这种结构理解为“先写内容，再处理附加上下文和提交”；空白与左右分组减少首屏同时争抢的控制。不能单凭截图断言认知负荷下降、点击成功率提高，或时钟图标的精确功能。暖橙按钮的淡色也不能证明它处于 disabled 状态。

实施借鉴：在自有界面中先定义 input area / auxiliary actions / model-or-mode / submit 四个语义位置；根据自身任务决定是否需要时钟形工具，不复制未知按钮。此截图的像素尺寸不是 CSS 尺寸、缩放率或窗口大小。

### A2. Mac Quick Entry（OV05-IMG1，1702 × 302）

来源：[Use quick entry with Claude Desktop on Mac](https://support.claude.com/en/articles/12626668-use-quick-entry-with-claude-desktop-on-mac)。源文件名含 2025-12-18；这仅是拍摄日期线索。原始资产清单称它为 mac_quick_entry_shortcuts，但实际图片不是快捷键设置页。

直接观察：
- 悬浮界面是单行、横向长条：左端品牌符号，随后输入光标与浅灰提示；右侧为 New Chat 与下拉箭头，最右是暖橙发送箭头。
- 可见控件共处一条垂直居中的水平轴，没有第二层工具栏或多列内容。
- 外层灰色背景与白色浮层之间有大范围柔和阴影；圆角使整个面板成为一个完整的浮动对象。发送按钮另有更紧的小阴影。
- 文本输入占了绝大部分宽度，右边的会话上下文和提交动作紧密相邻。

解释而非事实：相比 A1，Quick Entry 把输入和控制压缩到同一行，符合快速开始的任务；浮层阴影强化“暂时位于其他工作上方”的视觉关系。截图本身不证明 always-on-top 行为、展开动画、键盘触发或窗口拖拽，这些必须另引文字文档。

实施借鉴：以轻量浮层服务短输入，保持主输入长度，别把完整设置面板塞进条内。当前证据没有给出 Quick Entry 的展开态、附件态或错误态。

### A3. Cowork instructions 设置裁切（OV12-IMG1，1500 × 750）

来源：[Get started with Claude Cowork](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork)。拍摄日期未知，且该来源存在 Chat/Cowork 合并迁移提示。

直接观察：
- 上方是一段灰色说明文案，下面是大幅多行 textarea；二者左边界接近一致，表单阅读顺序自上而下。
- textarea 使用细浅灰边框和较温和圆角，内部几乎没有装饰。占位文案呈等宽外观，外部说明呈比例字宽外观；只能判断视觉类别，不能识别字体名。
- textarea 右下角有可见的斜线 resize affordance。
- 操作行在右下：Cancel 为白底细边框，Save 为黑底白字；两者在同一基线上，主次主要通过填充强度建立。
- 整张图片高度主要让给编辑区域，说明与按钮所占比重较小。表单密度很低，但截图也可能被特意放大裁切。

解释而非事实：这是内容编辑优先的设置形态，说明、编辑和确认被分成三层。黑色 Save 是重要反例：不能由聊天发送按钮推导出“所有 primary action 都是橙色”。不能据此推断整个 Settings 导航、分栏、表单间距或所有输入字体。

## B. 相邻状态与跨平台差异

### B1. Web/Desktop 语音入口（OV08-IMG1，474 × 232）

来源：[Use voice mode](https://support.claude.com/en/articles/11101966-use-voice-mode)。拍摄日期未知。

直接观察：composer 的右下裁切包含模型与下拉箭头，以及独立的暖浅灰底、圆角方形波形按钮。黑灰色圆角 tooltip 悬在按钮上方，白字、紧凑内边距与小阴影构成单独的一层。工具提示比面板边线醒目，但不占固定布局。

解释：这一状态更适合说明“图标需要补充语义，提示层按需出现”，不适合推导完整输入框或 tooltip 的触发方式。模型字样与 A1 不同，不可把两图无标注地拼成同一现状。

### B2. Web/Desktop 活跃语音控制（OV08-IMG2，247 × 108）

直接观察：左边是独立麦克风轮廓，右边浅蓝色圆角矩形内有三个蓝点与 Stop 文本。动作同时使用文字和图形，填色只覆盖可停止的控制。

解释：与只有波形图标的空闲入口相比，活跃状态更明确地显露终止动作。三个点在静态图里不证明动画，蓝色也不能被归纳为全应用通用“正在运行” token。

### B3. Mobile 深色输入框（OV08-IMG3，1320 × 415）

直接观察：深灰输入面浮在更暗的背景上；浅色占位提示位于上部。左下为加号与滑杆图标，右下为麦克风与更强对比的白色圆形波形按钮，形成与桌面相似的左右功能组。麦克风与波形并存，不能把两者视为同一个控件。

边界：这是移动端截图；可作为跨平台分组关系的对照，不能拿它的圆形按钮、深色值或尺寸填补 Desktop 暗色证据空缺。

### B4. Mobile 语音设置底部面板（OV08-IMG4，958 × 682）

直接观察：顶部中央有拖动条、底部有系统 home indicator；两个分组标题下分别排列大号圆角矩形选项。选中项使用更亮文字与边框，其他选项更暗；没有依赖大面积彩色底来表示选中。第一组选项右边被裁切，第二组可见三项。组间的垂直距离比同行项间距离更有分组作用。

解释：这种选中表达来自边框与字色的组合；仅静态图不能证明右边内容可横向滚动，也不能把它当成 Desktop settings 的网格规范。

## C. 2024 历史证据，单独使用

来源：[Collaborate with Claude on Projects](https://www.anthropic.com/news/projects)，发布日期 2024-06-25。四图均为 1920 × 1080。将它们称为“2024 官方宣传示意图”最稳妥：有实际产品界面元素，也有放大、裁切与演示包装，不等于未经处理的原始应用截图。

### C1. Document upload（OV21-document_upload）
- 右侧 Project knowledge 是带细边框的高容器，标题左对齐，Add 动作靠右；内部出现一个蓝边、淡蓝底的大投放区。
- 左侧项目标题、说明和输入框形成另一列，但画面被裁切，不能复原完整布局比例。
- 文件名拖拽浮标、数量徽记与光标覆盖在界面上；不能把这些全部归因于 Claude 自有组件。
- 米色/暖灰大面与蓝色操作反馈并存，说明历史时期也不是所有交互都依赖橙色。

### C2. Custom instructions（OV21-custom_instructions）
- 右侧知识面板自上而下是标题与 Add、虚线边框 instructions 入口、逐行文件列表。
- 文件类型图标与两层文字（名称、日期）构成重复行，图标列和文字列分别对齐。
- 深色说明浮层在入口旁展开，显著区别于浅色主界面；旁边的放大手形光标属于演示资产的一部分。
- 左侧可见衬线项目标题和正文样式，与右侧偏工具性的无衬线标签并置；只能说明这张历史样本有角色分工。

### C3. Artifact and chat（OV21-artifact_and_chat）
- 这是本批最完整的历史双栏图：左边对话、右边独立 Artifact 面板，共享上方项目/会话路径与操作区。
- 对话区有用户消息底色面、助手回复框、嵌入式 artifact 卡片与很小的回复操作条。输入框位于底部，工具信息视觉权重低于内容。
- Artifact 面板自身有标题栏、Preview/Code 切换、关闭按钮与底部状态/工具。深色代码内面与浅色应用外壳构成内容层与宿主层的分离。
- 回复正文及部分标题呈衬线外观，输入/工具与代码另有不同字体角色。代码区的语法配色是内容视图，不是应用壳的全局色板。
- 能据此确认 2024 年已有“聊天保持上下文、结果在相邻独立面板操作”的视觉构造，不能据此确认当前 Desktop 的默认栏宽或可拖拽实现。

### C4. Shared project chats（OV21-shared_project_chats）
- 左列先给大项目标题和简要说明，再给标签/叠放头像、主输入框、共享聊天摘要；右列是独立知识面板。
- 项目标题与摘要中的引用呈衬线外观，工具标签、元信息和知识文件名呈无衬线外观。
- 一侧围绕交流，一侧围绕资料，主要靠空间分列与柔和容器分隔，没有粗重彩色栏头。
- 头像、文件名与聊天文案是官方演示内容，本报告不把它们当作真实用户身份或私人材料。

## D. 可以进入原创设计规范的原则

- 用语义布局继承，而不是截图尺寸继承：主输入/上下文工具/模型或模式/提交分别占稳定位置。
- 让容器层级有差别：应用背景、输入面、可点击按钮、临时 tooltip 不必使用同一种边线或阴影。
- 用中性色承担绝大部分面积；强调色按动作语义和状态分配，不规定所有主要动作一律暖橙。
- 文本优先于装饰：大编辑区域、清楚的操作群和低权重元信息，比复刻品牌图标更有普适价值。
- 图标可以保持线性与轻量，但关键的终止/保存动作应有文字或其他明确语义支持。
- 在拥有自己的品牌和字体授权的前提下，可考虑“内容阅读字体 / 界面工具字体 / 等宽编辑字体”的角色分工；当前证据不要求照搬某个字体家族。

这些是基于样本的设计解释和原创实施建议，不是 Anthropic 发布的设计系统条文，也不是已验证的可用性结论。

## E. 明确不能据本组图声称的内容

- 当前 Desktop 整窗的侧边栏宽度、顶部模式标签、native chrome、窗口最小尺寸、响应式断点。
- 精确 CSS 颜色、阴影、圆角、间距、字号、line-height、字体家族或字体授权。
- 当前 Desktop 暗色模式全貌；本批深色全图是移动端。
- hover/focus/disabled/loading/error 的完整状态机、动效时长、键盘行为或无障碍合规。
- 所有账户已迁移到同一 Chat/Cowork/Artifacts 版本。

可公开分享的是本报告的原创观察与官方文章链接。原始图片仅作私有核验材料，不应作为设计规范附件、模板资产或整图图集分发。
