# 原创 AI 任务指标实验

这个标准库 Python 实验演示事件契约、运输去重、任务与尝试分母、成熟窗口、未知终态、顺序漏斗和条件延迟分位数。它是原创教学代码，不是 Claude 的实现。

## 运行

```bash
python -m unittest -v test_metrics_lab.py
python metrics_lab.py sample-events.jsonl 2000000
```

默认观察窗口为 600,000 毫秒；CLI 第二个参数是固定分析截止时点。所有输入都是合成数据，运行不需要网络或第三方 Python 依赖，也不会向任何系统发送遥测。

## 手算样例

样例有三个成熟任务：一个成功且确认价值、一个失败、一个未知。另有一个尚未完成观察窗口的任务。一条运输重复记录被去重，一个失败任务包含两次真实尝试。

- 分母：3 个成熟合格任务
- 首输出任务：2，成功任务：1，价值确认任务：1
- 任务成功率与价值确认率：都是 1/3
- 已观察首输出时延：100 ms 和 400 ms；最近秩定义的 P95 为 400 ms
- 重试任务：1；未成熟任务：1；运输重复：1

[固定输出](sample-result.json)应与命令行结果一致。26 个单元测试覆盖上述行为以及事件 ID 冲突、互相矛盾的终态、未知字段、采样、无效时间、乱序、未来事件、取消与零分母。

## 明确限制

- 输入必须能放入内存，没有流式 watermark 或跨批次状态。
- 仅支持未采样数据；不外推到未同意遥测的用户。
- 不能把 unknown 当成已观察到的 failure。
- 完成与首输出的分位数是条件分布，必须同时看未完成/无输出规模。
- 不是完整 attempt 状态机，不证明日志包含每个起止事件。`retry_task_count` 实际统计成熟窗口内有多个不同 attempt_id 启动的任务；当前也会计入 task_closed 之后的启动。生产实现应隔离此类时间冲突，不能把它直接当作已验证的真实重试率。
- 不计算因果效果、置信区间或生产级异常上报。
- 字段白名单不会自动识别标识符内的个人信息；真实系统必须单独生成用途受限的 ID，并管理保留和删除。
