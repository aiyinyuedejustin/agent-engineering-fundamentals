# 原创教学模型：记忆修改与能力开关

本模块从本书原创草稿整合而来，使用 Node.js 内置模块；不导入产品代码，不读取真实记忆，不连接服务器，不调用私有 API。所有组织、请求和存储内容均为合成数据。

## 运行

在本模块目录内，使用 Node.js 20+：

```sh
node --test memory-flags-model.test.mjs
node demo.mjs
```

或在实验室根目录运行 `python3 run_tests.py --demos`。无需安装依赖。

## 模型对应的问题

- `ScopedMutationQueue`：同一作用域按提交顺序执行，不同作用域可以独立推进。失败向调用方报告，但不会阻断后续操作。
- `applyQueuedOptimistic`：在队列中修改缓存；成功时用返回结果替换，失败先回滚，再允许下一次修改。示例把不存在和 `undefined` 缓存值视作同一种缺失状态。
- `LatestRequestGuard`：新请求开始或显式失效后，旧请求即使返回，也不能写成当前结果。它不取消底层操作。
- `decideAccess`：区分客户端开关未知、平台未开放、服务端状态和用户暂停。简化模型只把显式 `userEnabled: false` 视作用户暂停；没有把它设计为通用授权器。
- `readBoundedNumber`：拒绝非数字或非有限值，并限制有效远端数值范围。调用方需要提供有效的 fallback、min、max。
- `evaluateCapabilityGraph`：先列出依赖，再列出消费者；拒绝缺失依赖和循环。输入假定为已校验的能力表，不执行功能开关求值。
- `resolveFreshAccess`：新鲜快照可复用；过期或未来时间戳需要重新读取，读取失败不给予新动作许可。这是作者的防御性示例策略。

15 项测试覆盖顺序、并发、失败恢复、过期结果、用户暂停、依赖错误、数值边界和访问快照。测试验证的是原创模型的局部行为，不是产品服务端实现。

## 刻意省略

没有真实组织隔离、账号切换、数据库事务、多标签页缓存同步、服务端权限校验、特性实验分流、持久记忆生成、跨设备竞态或网络取消。作用域键和缓存由调用方提供；对同一缓存的写入必须使用同一队列才能维持这里的顺序保证。不要把这些内存模型直接用作生产权限或数据隔离边界。
