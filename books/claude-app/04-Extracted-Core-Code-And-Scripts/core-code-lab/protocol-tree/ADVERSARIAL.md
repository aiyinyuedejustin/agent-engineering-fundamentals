# 从能运行，到能挡住坏输入

一组正常样例通过，只能说明那组样例能运行。这里记录本书原创教学实现经过反例测试后补上的八个契约，方便直接迁移到自己的系统。

| 容易漏掉的输入 | 应明确的契约 | 为什么重要 |
|---|---|---|
| 行超限报错后继续喂换行 | 解析失败使实例进入终态，清空残留缓冲 | 否则被拒绝的数据可能在下一次调用重新变成合法事件 |
| 同一字符串按不同 chunk 切开 | 缓冲上限约束保留状态，而非本次 push 的总长度 | 网络如何切块不应改变同一份内容是否被接受 |
| retract 缺少或伪造索引 | 先验证非负整数，再改变内容 | JavaScript 数值强制转换可能把坏索引变成“删除全部” |
| 不在当前可见路径上的孤儿与环 | 先验证全图，再决定显示哪些节点 | 可见性过滤不能藏掉结构错误 |
| 第一个事件回调里触发 abort | 每次交付前后检查取消状态 | 一个 chunk 可以含多帧，不能只在读取 chunk 时检查 |
| 批次第二项无法 structuredClone | 全批预检、复制成功后再提交 | 否则“批量原子插入”会留下第一项的半完成写入 |
| 稀疏但合法的巨大 index | 根据已有索引二分找前驱，不逐个整数倒数 | 工作量应取决于记录数，而不是索引数值 |
| 属性引号内出现 > | 识别引号状态后再判定标签结束 | 单纯寻找下一个 > 会把标题截断并污染正文 |

## 1. 报错之后，状态也必须有定义

```js
const parser = new IncrementalSSE({maxLineCharacters: 6});
try {
  parser.push(new TextEncoder().encode('data: a'));
} catch {
  // 这不是一次可以忽略的提示：当前解析器已经终结。
}
// 后续 push 必须拒绝，不能让先前超限的内容借换行重新交付。
```

缓冲上限、非法配置、损坏输入和正常 EOF 都需要有明确的后续调用规则。另开一个新实例是重新开始；继续使用旧实例不是自动恢复。

## 2. 原子性必须覆盖准备阶段的异常

```js
// 第二条记录含有不能被 structuredClone 复制的函数。
const batch = [
  {uuid: 'a1', sender: 'assistant', parent_message_uuid: 'h1'},
  {uuid: 'a2', sender: 'assistant', parent_message_uuid: 'h1', content: () => {}}
];
// append 抛错后，a1 与 a2 都不应出现在任何索引中。
```

顺序应是“验证所有身份 → 准备所有副本 → 验证候选图 → 提交映射”。如果准备一条就写入一条，后续出错时需要额外回滚所有相关索引，复杂度会明显上升。

## 3. 取消只能承诺检查点之后不再继续交付

abort 不会倒转已发生的回调，也不保证底层 I/O 自动取消。教学消费者在拉取前、每次帧回调前后和 EOF 处理前检查信号：承诺的是合作式检查边界，不能写成“任意时刻都能原子停止所有副作用”。
