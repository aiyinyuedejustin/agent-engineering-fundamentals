# 原创教学模型：回合、权限与坐标

这些 Python 文件为本书重新设计，不是反编译代码、Claude 内部 SDK、兼容实现或可用的自动化代理。它们只操作内存对象与合成数据，不连接网络、不启动进程、不访问真实截图、不点击或输入。

运行：

```sh
# 在本模块目录中运行
python3 -B -m unittest -v
python3 -B model.py
```

四组可验证思想：

1. Session 与 process 生命周期分离，票据同时核对 Session 实例身份与 generation，让跨实例及过期 spawn/result 失效。
2. 审批 request ID 只能消费一次；取消一个会话不会取消另一会话。
3. Batch 中每个动作重新检查授权；失败后，之前动作不会自动回滚。
4. 图像 frame、显示器尺寸和显示器原点是不同单位，执行 owner 与 UI 所在机器也不同。

刻意简化：没有真实凭据、模型、MCP、系统权限、符号链接、文件系统授权、真实事件队列、子会话或跨进程取消。审批模型把所有参数变化拒绝，这是便于教学的保守设计，不代表产品每种工具都使用同一策略。坐标模型要求已知截图 frame，未复制观察到的无截图 fallback。方法名、数据组织与实现代码均为原创。

## SpawnTicket 的本地归属合同（原创加固）

`begin()` 返回绑定当前 Session 实例的票据。`attach_process` 与 `result` 必须同时通过 `ticket.owner is self` 与 epoch 检查。同值 session 名称、相同 dataclass 字段或两个计数器都等于 1，不表示同一对象。票据用身份相等而非结构值相等；调用者应传回原票据。入口检查的是owner与epoch，并不要求票据对象本身是原对象。

owner 是本进程对象引用，不是安全凭证，也不是跨进程序列化、认证或持久化恢复协议。持有引用的本地 Python 代码仍可构造对象，本例不防恶意同进程代码。注册表替换对象后，旧票据不能接管或结算新对象；这不自动停止旧对象，旧对象的清理仍由调用者负责。

本次只补归属检查，不改变 `begin`/`stop` 的 epoch 递增、暖复用保留同一 epoch、排队成功返回 continue 或取消清队列的规则。模型的 process 只是布尔模拟值，没有真实进程、EOF 或退出等待 API；不能以这里的 idle/False 推断真实进程已退出，也不改变真实适配器退出前的 active 合同。

新增 `test_owner_binding.py` 覆盖同 epoch 跨实例、注册表替换、旧成功/错误结果、停止重启、暖复用与同实例合法票据。独立 JavaScript skill 已按当前票据对象身份核对 attach/result/eof，无需同步改成较弱的值比较。以上为本书原创合同加固，不是 Claude 漏洞结论。

## 接入真实 runner 前再区分三个寿命

- owner是强引用：保存票据也会保留Session，票据不用时应释放。它不是自动清理旧Session的注册表。
- `eq=False`改变票据的相等行为，不禁止本地代码重新构造同owner、同epoch的票据；这类票据仍可通过当前检查。
- epoch属于初始化/进程寿命，暖复用时不变。本模型没有逐回合结果去重：同一暖进程的迟到旧result仍可能匹配。接入真实runner时，应另行绑定turn/request身份并消费去重，不能用这个进程票据替代回合票据。

46项模块测试包含原28项、归属回归11项及独立边界7项。独立测试把上述保留边界写成可见例子，不把它们包装成端到端执行保证。
