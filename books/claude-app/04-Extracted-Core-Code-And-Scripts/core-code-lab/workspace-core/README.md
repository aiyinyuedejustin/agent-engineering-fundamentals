# 原创教学模型：Artifacts 与沙箱工作区

本目录配合 Vol. 7，演示版本选择、预览门控、内容确认、窗口消息入口校验和工作区显示状态。代码由本书重新编写，不是提取出的产品源码、内部 SDK 或协议兼容实现。

## 运行

需要 Node.js 20 或更新版本。没有第三方依赖，不用安装软件包。

```sh
# 在本模块目录中运行
npm test
npm run demo
```

也可以直接执行：

```sh
node --test workspaces-model.test.mjs
node demo.mjs
```

目录内容：

| 文件 | 用途 |
|---|---|
| `workspaces-model.mjs` | 原创纯 JavaScript 模型 |
| `workspaces-model.test.mjs` | 12 个测试，覆盖正常、过期、重复与失效路径 |
| `demo.mjs` | 使用合成版本和 HTML 字符串演示状态转换 |
| `package.json` | 本地运行命令；没有依赖项 |

所有输入都是内存对象或合成字符串。示例不会执行 HTML/React，不创建 iframe，不联网、不导入产品代码、不调用应用接口、不获取用户文件或凭据。`<h1>` 只是文本。

## 哪些思想在模型中

- 选中版本的优先级：实时生成/新助手消息占位优先最新；否则按版本 UUID、tool-use ID、消息 UUID 查找；最后回退最新。
- “当前 artifact 正在生成”要求对话正在流式输出、最新版本未关闭、最新版本没有服务端记录三个条件同时成立。
- HTML、React、SVG、Mermaid 在这一实时状态下显示源码；类型和展示模式共同决定渲染路径。
- 内容确认具有 epoch。旧成功响应不能确认新内容；确认前到达的请求不能借用稍后的确认。
- 同一 type/body 已经确认时，重复发送可以沿用 epoch。未确认内容即使文本相同，重新发送仍推进 epoch。类型改变也使确认失效。
- Window 消息的 origin 和 source 必须分别检查；payload 校验另行进行。
- 最小化记住上一个可见模式，重复最小化不覆盖恢复目标。

## 刻意省略与设计建议

`ContentEpoch` 只表达内容投递的局部不变量。真实客户端还包含 consent epoch、用户激活、artifact 身份、待处理对话框、空内容清理及排队请求。模型的 `replace` 对应一次已允许的内容投递，不包含 ReadyForContent、非空输入等前置条件。`mayUseCapability` 返回真，只表示此教学模型的内容确认条件满足，不代表真实权限已获准。

`inspectInbound` 只模拟 Window 消息路径，不是 MessagePort 消息验证器。真实协议中的 schema、握手、频率限制、去重、权限检查和能力分发均未实现。不要把本模块用于生产安全边界。

`withDeadline` 是作者提出的防御性改进，不能据此断言目标客户端的通用 RPC 自带超时。它只限制调用方等待时间，不会取消底层工作，也不会自动结算其他在途请求。生产实现还需要请求表清理、关闭时逐项 reject、取消信号及逐操作期限。

代码不实现远端编译器、库加载、CSP、SVG 清理、Mermaid 配置、服务端持久化或协同编辑。测试通过只验证原创模型，不能证明产品真实运行或安全性。
