# 评测审查清单

这是本研究综合形成的操作清单，不是某一机构的认证标准。

## A. 目标与样本

- [ ] 要支持的决策是什么？
- [ ] 被测能力有清楚的边界，还是含糊的“智能/安全/agentic”？
- [ ] 样本来自目标使用分布，还是困难集、便利样本、公开题？
- [ ] 语言、领域、长尾、高风险任务是否分开报告？
- [ ] 独立抽样单位是题、文章、用户、会话还是仓库？
- [ ] 样本数与最小关心差值有功效依据吗？

## B. 被测系统

- [ ] 模型 ID、版本、调用时间、system prompt 可追踪吗？
- [ ] 工具、网络、代码执行、检索、记忆与人工帮助是否一致？
- [ ] 推理预算、总 token、时间、尝试次数、选择策略是否一致？
- [ ] 比较的是模型还是完整系统，表述是否匹配？

## C. 评分

- [ ] 什么是成功，什么是部分成功，什么是不可接受的副作用？
- [ ] parser 是否有单元测试、边界测试、分数范围与唯一 verdict 检查？
- [ ] 参考答案/测试是否经过正负对照与多种正确解验证？
- [ ] 测试“未执行”和“执行后通过”能否区分？
- [ ] judge 是否在独立、分层、贴近用途的标注集上验证？
- [ ] 是否分别报告正确率、顺序一致率、tie、解析失败和分层误差？
- [ ] 环境错误、超时、拒答和缺失结果如何进分母？

## D. 统计

- [ ] 有逐题配对记录，而非只有总体均值吗？
- [ ] 区间对应任务抽样、模型随机性还是两者？
- [ ] 聚类和重复采样结构被正确处理了吗？
- [ ] 是否直接对差值计算区间，而非比较区间是否重叠？
- [ ] 多模型、多指标、多提示词选择有说明吗？
- [ ] 预先设定的分析与事后探索能否区分？
- [ ] 不显著是否被误写成相同/等效？
- [ ] 小差距是否仍在成本、延迟、风险上有实际意义？

## E. 污染与版本

- [ ] 检查的是题目、答案、来源材料还是近重复？
- [ ] 未检出是否被错误表述为无污染？
- [ ] 测试集是否已在开发中被反复查看？
- [ ] 工具或网络是否让系统访问公开解答？
- [ ] 结果绑定任务 release、评分器 commit、依赖/容器版本吗？
- [ ] benchmark 更新后是重评分还是重新生成答案，理由清楚吗？
- [ ] 当前资料是否已经撤回或修正旧推荐？

## F. 发布最小包

1. 目标与适用范围。
2. 任务清单及样本/簇数。
3. 完整运行配置和版本。
4. 原始输出与逐题评分，依法处理隐私和许可证。
5. 评分源码及测试。
6. 失败分类、无效样本和分母说明。
7. 差值、区间、成本和延迟。
8. 污染检查、限制、变更记录与复现步骤。

可从 [来源账本](sources.md) 和 [本地实验](experiments/README.md) 核查本清单背后的证据。
